mac-checkup

电脑空间快满、睡眠耗电、想清理又怕删错东西的时候，它先帮你查清楚，再由你决定动什么。

「帮我清理一下电脑」是最容易出事的一句话。模型知道 du，也知道 rm，但它不知道你的下载目录里放着一个跑了一半的项目，也不知道有些大目录删掉之后要重新授权一遍才能用。

所以这个 Skill 的核心不是命令清单，而是流程和边界：只读扫描 → 出报告 → 你逐条确认 → 才动手。

它帮你查四件事

  • 磁盘占用与可清理项

    扫一遍常见的大块占用，给出可审阅的清理建议。你点头之后，它把允许处理的项目移进废纸篓——注意是移进废纸篓，不是直接删，随时能捞回来。

  • 睡眠与异常唤醒

    读取并汇总一段时间内的睡眠与唤醒记录，帮你看清机器为什么半夜会醒、为什么合盖之后还在耗电。它给的是事实和时间线，不是「帮你省电 30%」这种话。

  • 电池与充电习惯

    看电池状态，给电源策略建议；如果它觉得你的充电习惯值得调整，会提醒一句，可以挂一个定时提醒。设置这条路需要你自己在系统里点，它不替你改。

  • 后台自启项

    把开机自启和后台常驻的服务列出来，让你自己判断哪些还需要。清单本身不难，难的是不误伤系统组件。

安全流程是它真正的设计价值

这四步不是文档里的建议，是流程里绕不过去的关卡。任何一步都不能跳。

  1. STEP 01 只读扫描 这个阶段不写任何东西，只收集信息。
  2. STEP 02 出报告 按固定结构输出，每条建议都带理由和影响范围。
  3. STEP 03 你来确认 逐条过，不要的一律不做。单批最多 10 项。
  4. STEP 04 执行与回滚 删除走废纸篓；电源改动前先备份，改后可回读、可回滚。

绝不 rm：所有清理都是 mv 到废纸篓，误删能还原。

受保护路径直接拒绝：文档、桌面、照片图库、.git、iCloud 同步目录、应用配置，脚本层面就不处理，不是靠模型自觉。

电源改动必须留后路：改之前备份当前设置，改完回读一遍确认生效，最后把回滚命令交给你。

为什么值得做成 Skill

这些坑都不是技术难点，是踩过一次才知道的事。写进 Skill 之后，下一个用的人不用再踩一遍。

  • 01

    移进废纸篓不等于释放空间

    这是最反直觉的一条。文件移进废纸篓之后 df 的数字一点没变，还得再清空废纸篓才算真的腾出空间。报告里会把这两步分开写，避免你以为已经好了。

  • 02

    80% 充电上限没有命令行开关

    网上流传的「一行命令设置充电上限」并不成立。所以这里只做提醒，不做承诺——能给的是一句该充电了，不是一个自动生效的限制。

  • 03

    Agent 会读写，所以要给它围栏

    Skill 是交给 Agent 执行的东西，它有能力真的动文件。围栏不能只写在说明里，得落在脚本里：路径检查、批量上限、两阶段交付，都是代码执行时才生效的约束。

边界

它不是一键优化工具。能不能清理、要不要改电源策略，最终都由你决定。

清理完成只代表文件进了废纸篓，磁盘空间要等你清空废纸篓之后才会变。

电池部分给的是状态和建议，不承诺延长寿命多少个百分点；这类数字我没法验证，就不写。
