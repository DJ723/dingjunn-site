记忆最难的不是存，是决定什么时候别读

给 Agent 加记忆很容易：建一张表，把历史塞进去，每轮检索一下。难的是判断这一次该不该读——在医疗场景里，用错旧记忆比没有记忆更危险。

医路通里有一类用户行为是别的场景少见的：把体检报告传上来，问几个问题，然后隔两三个月再回来，接着问「我上次那个指标怎么样」。

这类回溯需求天然需要记忆。但医疗数据和聊天记录不一样，它有半衰期：三个月前的血脂结论，今天只能作为对照；半年前的用药建议，今天直接引用就是错的。所以整套设计里最关键的一个决定，不是「怎么存」，是——

每一轮都要先判断：这次该用当前附件、用本轮会话的报告、还是用长期记忆？三者只能有一个当证据主体。

先定意图，再定证据

接到一条消息，系统先做一次意图判定，输出四样东西：意图、用不用当前附件、用不用长期记忆、证据优先级。七种意图对应七套开关：

意图典型问法读长期记忆证据优先级
分诊「胸口疼，要看哪个科」否知识库优先
历史查询「我上次体检尿酸多少」是知识库优先
纵向对比（纯文字）「比去年是不是降了」是知识库优先
纵向对比（带新报告）传新报告 + 「和之前的比」是当前附件优先
新旧同问传新报告 + 「这个严不严重」是当前附件优先
报告追问「这个箭头什么意思」否本轮会话报告
普通咨询「晚上吃太油怎么办」否知识库优先

两个设计要点值得单独说。

一、分诊场景强制关闭记忆。问「胸口疼看哪个科」的时候，需要的只有当前症状。这时候如果检索出「三个月前你说过自己有胃食管反流」，模型很可能把旧结论当解释，把一次需要排查心血管的胸痛，说成老毛病。这是记忆能造成的、最典型的一类伤害。

二、传了新报告时，以新报告为主证据。只要本轮带了附件，历史记忆就退居对照位——它的作用是给出参照值，而不是替代当前数据。代码里这条体现为一个显式的字段 evidence_policy = current_attachment_first，不靠提示词口头约束。

检索画像：把报告压成几个词再去查

直接拿用户那句话去查历史报告，命中率很低。用户说的是「我上次那个指标咋回事」，报告里写的是「低密度脂蛋白胆固醇」。中间隔着一次术语翻译。

所以检索前会先构造一份画像：从这次的消息和报告解析结果里，抽出临床系统（心血管、消化、内分泌……）、报告主题（血脂、肝功能、影像），再加上报告标题，各组取前 8 个词，拼成检索语句。相当于把用户的自然语言，翻译成报告自己使用的词汇。

没做好的地方

这套设计有个明显的短板：意图判定在模型不可用时会退回到关键词兜底——「比」「变化」「复查」「之前」这类词触发对比意图。它的问题是脆弱：

  • 漏判：「和上回那个单子比呢」不含上述任何一个词，会掉进普通咨询。
  • 误判：「我没有之前的报告」也含「之前的报告」，会被判成历史查询，然后去检索一批不存在的东西。
  • 没有时间权重：现在检索只按相关性排序，三个月前和两年前的报告权重一样。医疗数据显然该随时间衰减。

如果继续做，顺序应该是：给每份报告带上检查日期，检索分数乘以时间衰减；再补一层否定检测（「没有」「不是」「别」），避免把否定句判成肯定意图。这两件都不难，但都必须在评测集上验证——记忆这类模块最容易越加越乱，改一处坏三处。

一句总结

做记忆时我以为难点在存储和检索。做完才发现，真正的设计量在「不该读的时候不读」：分诊时关掉、有新证据时降级、旧数据加权衰减。记忆的价值取决于阈值，不取决于容量。
